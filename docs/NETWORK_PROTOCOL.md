# Jelly Bean Signage ローカル通信仕様

この文書は Jelly Bean Manager と Jelly Bean Signage の通信契約です。ここに書かれた API は、実装が完了するまでは設計仕様です。

## 通信モデル

- ManagerがSignageのローカルIPアドレスとポートへ接続します。
- 初期ポート案: TCP 8765
- 通信範囲: 同一Wi-Fi内のLAN
- Signageがインターネットへ接続することは必須ではありません。
- JSONはUTF-8で送受信します。
- HTTPサーバーはAndroid API 17で利用できるJava標準機能を基礎に実装します。

## API v1

### GET /api/v1/status

接続確認と状態取得。ペアリング前にも利用できます。

応答例:

```json
{
  "app": "Jelly Bean Signage",
  "apiVersion": 1,
  "appVersion": "0.0.1",
  "paired": false,
  "displayMode": "standby"
}
```

### POST /api/v1/pair

初回ペアリング。Signageの画面上でユーザーが確認できる短時間有効なペアリングコードを送ります。

要求例:

```json
{
  "code": "123456",
  "managerName": "My Phone"
}
```

成功時は以後の要求に使うランダムな認証トークンを返します。例のコードは説明用であり、実際のコードとして使用してはいけません。

### GET /api/v1/config

認証済みManagerが現在の表示設定を取得します。

### PUT /api/v1/config

認証済みManagerが表示設定を更新します。許可する設定キーをホワイトリストで検証し、値の型と範囲を検査します。

### POST /api/v1/message

認証済みManagerが短いテキストメッセージを表示用設定へ保存します。メッセージの長さを制限します。

### POST /api/v1/media

認証済みManagerがメディアファイルを転送します。ファイル名はサーバー側で安全化し、アプリ専用ディレクトリ内だけに保存します。転送完了・サイズ確認後にコンテンツ一覧へ登録します。

## 認証と安全性

- 初回ペアリングコードはSignageの画面上で確認できるようにします。
- ペアリングコードは短時間で失効させ、試行回数を制限します。
- ペアリング後は十分にランダムなトークンを要求ヘッダーで送信します。
- トークンをURLやログへ出力しません。
- ファイル名に含まれるパス区切り文字や親ディレクトリ参照を拒否します。
- 任意のシェルコマンド実行、任意パスへの書き込み、任意URLへのプロキシ機能は提供しません。
- ローカルHTTPは暗号化されません。信頼できるネットワーク内でのみ利用してください。

## エラー応答

すべてのエラー応答はJSONで返します。

```json
{
  "error": "invalid_request",
  "message": "Request could not be processed."
}
```

主なHTTPステータス: 400（入力不正）、401（未認証）、404（未対応API）、409（状態不一致）、413（サイズ超過）、500（内部エラー）。

## 実装方針

APIサーバーは独立したクラスとして実装し、UIスレッドをブロックしません。受信した設定は永続化してから表示側へ反映し、通信断やアプリ再起動後も最後に保存した設定を維持します。
