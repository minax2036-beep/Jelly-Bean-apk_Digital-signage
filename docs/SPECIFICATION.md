# Jelly Bean Signage 仕様書

## 1. 目的

Jelly Bean Signage は、Android 4.2.2（API Level 17）端末を、個人用の壁掛け情報ディスプレイとして活用するアプリです。業務用サイネージ管理を前提とせず、勉強・日常生活・趣味に使える表示環境を目指します。

## 2. 対応環境

- 最低対応 OS: Android 4.2.2 / API 17
- 実装言語: Java
- UI: Android標準View
- 外部ライブラリ: 必要最小限。API 17との互換性を優先
- ビルド: GitHub Actions
- ネットワーク: 同一Wi-Fi内のローカル通信
- 基本機能: インターネット接続なしでも動作

## 3. アプリの役割

### Jelly Bean Signage（このリポジトリ）

壁掛けディスプレイ側で動作します。

- 時計・日付の表示
- 画像スライドショー
- 動画再生
- 音楽再生
- 月間カレンダー
- 設定の端末内保存
- Managerからの設定・コンテンツ受信（段階的に実装）
- 通信断の際も、端末に保存済みのコンテンツを表示

### Jelly Bean Manager（別リポジトリ）

スマートフォン側から表示内容を編集します。

- 表示設定の変更
- 画像・動画などの転送
- 表示メッセージや勉強用情報の編集
- 表示側との接続・ペアリング

## 4. 画面設計

### 表示画面
通常利用時は、操作ボタンを目立たせず、画面全体を表示領域として使います。時計や日付などのオーバーレイは設定で表示・非表示を切り替えられる構造を目指します。

### ホーム画面
アプリの機能へ移動するためのランチャー画面です。壁掛け表示の自動開始と、ホーム画面を利用する操作モードを混同しないようにします。

### 設定画面
端末上での設定に加え、Managerとの接続状態、ペアリング操作、受信した設定の状態を確認できるようにします。

## 5. メディアと保存

- 既存の画像・動画・音楽再生機能は段階的に整理して再利用します。
- Managerから受信したファイルは、アプリ専用の保存領域に保存します。
- 受信中のファイルを直接再生せず、転送完了後に有効なコンテンツとして登録します。
- 不完全な転送や未対応形式で、現在の表示内容が壊れないようにします。
- Android 4.2.2で再生できるかは、端末のデコーダーとメディア形式にも依存します。

## 6. Wi-Fi連携

ManagerとSignageは同じWi-Fiネットワーク内で直接通信します。クラウドや外部サーバーは必須にしません。

- Signage側がローカルHTTP APIを提供します。
- ペアリングコードで、ユーザーが意図したManagerを接続します。
- ペアリング後の変更要求には認証情報を必要とします。
- APIは必要な操作だけを公開し、任意のコマンド実行や任意パスへのファイル書き込みを提供しません。
- 通信できなくても、保存済みの設定とメディアで表示を続けます。
- HTTPはローカルネットワーク内に限定します。信頼できないWi-Fiではペアリングしないでください。

APIの具体的な仕様は [NETWORK_PROTOCOL.md](NETWORK_PROTOCOL.md) を参照してください。

## 7. 開発順序

1. API 17対応と既存機能のビルド安定性を確認
2. 表示画面と再生処理を分離・整理
3. ローカルAPIと接続状態表示
4. ペアリングと認証
5. メッセージ・表示設定の同期
6. メディア転送とプレイリスト同期
7. 起動後の自動表示、長時間動作、復旧処理を検証

## 8. 互換性のルール

- AndroidXや新しいJetpack APIを無条件に導入しない
- Java APIもAndroid API 17で利用可能か確認する
- 新しいOSでしか使えない機能には代替手段を用意する
- UIやネットワーク処理をメインスレッドでブロックしない
- 長時間表示時のメモリ使用量に注意する。特に高解像度画像を一括ロードしない
